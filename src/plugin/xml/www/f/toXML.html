toXML - Convert data to an XML string

toXML(data:object, template?:string):string
This is part of the xml plugin. You must load the plugin via either -lxml on the shell command line, or a plugin xml; line in a script.

The toXML() function generates an XML string. You can invoke it with or without a template string.

Without a template string

It is the opposite of the XML parser; if you take parsed XML data and feed that to this function, you should get the same XML back (possibly with minor formatting changes).

Some quirks are:

  • The data will almost always be an object. All members of the object are converted into a series of XML tags. Usually this will be a single member with data, possibly with a "?xml_" member to generate the "<?xml ?>" meta-tag.
  • Each member is either a "normal tag" member whose value represents the contents of the tag, or an "attribute" member whose name has an added suffix (usually "_") and whose value must be an object giving the names and values of the attributes.
  • If a "normal tag" member's value is an array, the tag will be repeated for each element of the array.
  • If there's a "key" member but no "key_" member, then the tag will have contents but no attributes. If there's a "key_" without a corresponding "key", then the tag will have attributes but no content.

The formatter uses the same pretty and tab config settings as the JSON formatter. It also uses the plugin's attributeSuffix option to control what suffix the data keys should use to denote attributes rather than contents.

With a template string

This is intended to give you precise control over the XML format. This matters because many SOAP servers are very picky. The template string is basically a framework XML document, with added notations to say what should get inserted where. The supported notations are:
name="$key" In a tag attribute, replace $key with the value of data.key. If that value is missing, null, or "" then substitute nothing, leaving an empty set of quotes.
*name="$key" In a tag attribute, replace $key with the value of data.key and delete the "*". If that value is missing, null, or "" then delete the entire attribute including the name= part.
<tag>$key</tag> In the content between tags, replace $key with the value of data.key. If the value is missing, null, or "" then replace it with nothing.
<tag>$$key</tag> In the content between tags, treat $$key (with double dollar signs) like $key except that $$key will substitute the value of data.key verbatim, while every variation of $key will replace XML's special characters with entities to ensure that legal XML. This means that $$key can be used to insert a chunk of precomposed XML into a template.
<*tag>$key</tag> With a "*" before the tag name, delete the "*". If no non-empty substitutions took place (either in attributes or the content) then delete the entire tag.
$[key ... $] Loop over data.key, assuming that value is an array. If it is missing or null then treat it like an empty array; i.e. skip the content entirely. If it is an object, string, number, or boolean then treat it like a single-element array.

For elements that are objects, any substitutions within the loop will look for key first in that element. If you use nested loops, it'll look in the innermost first, then the next innermost, and so on, using data as the final fallback.

For elements that are strings, numbers, or booleans, you can use $this to access the element's value, or $that to access the next nested non-object.

The template string must have balanced <tag>...</tag> pairs. It knows that <?...> and <!...> don't need closing tags. It also allows you to use <tag/> if there is no content.

Examples
toXML({foo:"bar"}) "<foo>bar</foo>" The simplest possible example. The key "foo" becomes a tag name, and the value "bar" becomes the content. Since it returns a string, the entire thing is enclosed in quotes.
print toXML({"?xml_":{version:"1.0"},po_:{number:1106},po:{partno:["CR2032","18650"]}) <?php version="1.0" >
<po number="1106">
  <partno>CR2032</partno>
  <partno>18650</partno>
</po> This is a more complex example. We use the print command so you can see the formatting (no added quotes, no backslash escapes). The object has three members: "?php_" which generates the <?php ?> tag, and "po_" and "po" which provide the attributes and content of the <po> tag. The string is formatted because the pretty option is turned on. The content of the <po> tag contains single "partno" member, but the member's value is an array so the XML contains multiple <partno> tags.
var obj = {a:[{b:1},{b:2}],c:3}; var template = "<foo><test1 *attr=\"$d\"></test1><*test2 attr=\"$d\"></test2>$[a<test3 b=\"$b\" c=\"$c\"/>$]</foo>\n"; print obj.toXml(template); <foo><test1></test1>test3 b="1" c="3"/><test3 b="2" c="3"/></foo> Here's a nice meaty example using a template. The <foo> tag is copied without change. The <test1> tag has its attribute deleted because there's a "*" before the attribute name and the data doesn't contain a member named "d". The <test2> tag is deleted entirely because there's a "*" before the tag name, and again the data doesn't contain a member named "d". The $[a notation causes the <test3> tag to be repeated for each element of array obj.a; in $key substitutions, it pulls obj.a[].b for $b, and obj.c for $c. Also, note that <test3> ends with "/>" so toXML() knows that there is no content or closing tag.
Notes
  • For data from this plugin's XML parser, toXML() is intended to recreate the original XML pretty well when used without a template. No guarantees though. In particular, whitespace around string values may be lost.
  • The data argument is used very differently depending on whether you use a template or not. Without a template, the structure of data guides the structure of the resultant XML. With a template, the data will mostly just contain assorted values, not necessarily structured the way it's intended to be output.
  • The template syntax is very flexible, but you may still encounter situations that it can't handle. The solution here is to use toXML() wrapped in whatever edj logic necessary to create chunks of XML, and then use toXML() one final time with $$key in the template to say where those chunks should be inserted.
  • There is no way to make edj automatically output its results in XML instead of JSON. To display data as XML, you must use print toXML(),"\n".
