How to Add a Function (in C)

2025-05-10

Adding C functions to edj is fairly easy. Most plugins do it. When used in an edj expression, the arguments are collected into an array which is passed to the C function as a single argument. The arguments are automatically freed. The return value can't directly use any data from the arguments, but it can use copies. Functions must be registered with the edj library before they can be used in edj expressions. Aggregate functions can also be implemented. Resources used in the aggregate data can be automatically freed.
This article describes how to add a function, written in C. We'll start with a simple function, and then move on to aggregate functions. If you're only interested in using edj's expressions and script language, not extending it, then you can skip this article.

You'll see the edj_t data type used a lot in this article. It's used to represent JSON values, including just about all data in an edj script. See the The edj_t Structure for more info, if you're curious.

Behavior of a function

Each function is passed an array of arguments (as a edj_t with ->type=EDJ_ARRAY), and returns a edj_t result. Here's a quick example: 
	/* This is C code, not edj script.  It defines a function which returns
	 * a string of hyphens of a given length.
	 */
	edj_t *jfn_hrule(edj_t *args, void *agdata)
	{
		int	length, i;
		edj_t	*result;

		/* Check arguments */
		if (args->first->type != EDJ_NUMBER
		 || (length = edj_int(args->first)) < 0
		 || args->first->next != NULL)
			return edj_error_null(0, "The \"%s\" function takes non-negative number", "hrule");

		/* Allocate an edj_t string as the result */
		result = edj_string("", length);

		/* Fill it with hyphens */
		for (i = 0; i < length; i++)
			result->text[i] = '-';

		/* Return it */
		return result;
	}

The agdata parameter is there mostly for the benefit of aggregate functions, described later in this article. Most normal (non-aggregate) functions can ignore it but you should still declare it to avoid compiler warnings.

I'm not sure I should say this since it's likely to change in the future, but for now if your function uses a regular expression as an argument, then the args array will have a null where the regular expression was passed, and the actual regex_t (see "man 3 regex" in Linux) will be passed as the agdata. Otherwise agdata can be a pointer to the current edj_context_t.

Accessing parameters

The args parameter is a edj_t array. You can assume it will never be a deferred array. This means you can use args->first to find the first argument, args->first->next for the second, and so on.

The whole args array will be freed by the edj library after your function returns. There are two consequences to this:

  • You don't need to free the arguments when you're done. That happens automatically.
  • The value that your function returns can't include any part of the args edj_t tree directly. (This is discussed a bit more in the next section.)
You should always check the types of arguments. Start by checking the ->type field against the basic JSON types such as EDJ_STRING or EDJ_NUMBER. If you need more detailed constraints than that, do it. The example at the top of this article checks to make sure the first argument is a EDJ_NUMBER, that it isn't negative, and that no other arguments were passed.

Each built-in function is always passed at least one argument. If the expression that invokes it doesn't explicitly pass an argument, then true will be assumed. Thus, you can assume args->first is never NULL.

Returning a value

Each function returns a edj_t value.

The value should be freshly allocated. You cannot reuse parts of the arguments in your return value, because the arguments are automatically freed after the function returns. If you want to use part of the arguments in your response, use a copy instead, e.g. by edj_copy().

Simple data types are easy to return, because there are functions to do exactly that:

I don't want to get too deep into creation of arrays and objects, but briefly: Use edj_array() or edj_object() to allocate an empty array or object, and then use edj_append(container, data) to add data to it. For objects, the data that you add must be allocated via edj_key(key,value) where key is a simple C string, and value is a edj_t. 

	edj_t *array = edj_array();
	edj_append(array, edj_from_int(1));
	edj_append(array, edj_from_double(1.5));
	edj_append(array, edj_string("Hello World", -1));

	edj_t *object = edj_object();
	edj_append(object, edj_key("sample", array));

	/* This leaves object = {"sample":[1,1.5,"Hello World"]} */

Returning an error

To return an error, use the edj_error_null(where, format, ...) function.

The where argument is either NULL or a pointer into a memory-mapped script file to indicate where the error was detected. I suggest you just pass NULL there.

The format string is a printf-style format string, meaning %s gets replaced by a string parameter, %d by an int, and so on. It serves two purposes: to provide a default text message in case no translation is available, and to specify the quantity and types of any extra parameters. The format may optionally include a translation key at the start — an alphanumeric word followed by a colon, used to guide message translation.

Registering the function

Once your C function is written and compiled (probably in a plugin), it must be registered to make edj aware of it. Functions are registered via the edj_calc_function_hook() function. This is passed the function name, a string describing the parameters, a string describing the return type, and a pointer to the C function. The parameter and return type strings should ideally resemble TypeScript declarations, though they're basically just comments so it isn't critical. 
	edj_calc_function_hook("hrule", "width:number", "string", jfn_hrule);

Aggregate functions

Aggregate functions accumulate results across multiple elements of an array, and return a single result. Examples are the avg() and count() functions.

In edj, an aggregate function is implemented as a pair of C functions: One to do the aggregation, and one to return the final result. For example, the aggregation half of the avg() function counts of the items seen, and the sum of their values. The result half would return null if the final count was 0, or compute the average and return that if the count was non-zero.

Aggregate functions invariably need a bit of persistent storage space. For example, the avg() function needs to store the count and sum. The edj library allocates space, initializes it to all-zeroes before the first call, and then passes a pointer into the functions via the agdata parameter. It's passed as a (void*) but functions can cast it to a pointer to whatever data type they actually need.

Registering an aggregate function is a lot like registering a "normal" function, except that we need extra arguments for the aggregator function pointer, the size of the aggregate data required, and flags to optionally request automatic freeing of allocated resources.

Here's an example that defines a widest() aggregate function which returns the widest string value. 

	/* Define a type for storing the aggregate data we need */
	typedef struct {
	    edj_t	*str;
	    int		width;
	} agwidest_t;

	void jag_widest(edj_t *args, void *agdata)
	{
		agwidest_t *ag = (agwidest_t *)agdata;
		int	width;

		/* Ignore non-strings.  We could convert non-strings to strings
		 * via edj_serialize() but I'm trying to keep this simple.
		 */
		if (args->first->type != EDJ_STRING)
			return;

		/* Find the width of this string */
		width = edj_mbs_width(args->first->text);

		/* If longest so far, remember it.  If some other was being
		 * saved before, then free it now.
		 */
		if (!ag->str || width > ag->width) {
			if (ag->str)
			      edj_free(ag->str);
			ag->str = edj_copy(args->first);
			ag->width = width;
		}
	}

	edj_t jfn_widest(edj_t *args, void *agdata)
	{
		agwidest_t *ag = (agwidest_t *)agdata;
		edj_t	*result;

		/* If no strings were ever seen, return null */
		if (!ag->str)
			return edj_null();

		/* Return the widest string.  Clobber the value in agdata
		 * so it isn't freed right away.
		 */
		result = ag->str;
		ag->str = NULL;
		return result;
	}

	/* ... and later, in some initialization code somewhere */
	edj_calc_aggregate_hook(
		"widest",		/* name of the function in edj expressions */
		"s:str",		/* arguments -- a single string each time */
		"str",			/* return type is also a string */
		jfn_widest,		/* the function that returns the final value */
		jag_widest,		/* the function that finds the widest-so-far */
		sizeof(agwidest_t),	/* amount of storage space needed. */
		EDJFUNC_EDJFREE);	/* automatically free the edj_t in agwidest_t */
It could be used like this:
["one","two","three","four"] #^ widest(this) "three" The widest string in the array is "three".

Automatically freeing aggregate data

The bit about automatically freeing resources in the agdata requires a bit more discussion.

There are two flags you can pass to edj_calc_aggregate_hook() for the final parameter: EDJFUNC_FREE and EDJFUNC_EDJFREE. For EDJFUNC_FREE, the first bytes of the agdata are assumed to be a pointer to memory that was allocated via malloc() or its friends; when the agdata is no longer needed, if those bytes represent a non-NULL pointer then free() will automatically be called on that pointer, to free whatever it was pointing to. The EDJFUNC_EDJFREE flag does the same, but assumes it is a edj_t pointer which must be freed via edj_free(). If you use both flags together (via the bitwise-OR operator, |), then edj assumes the agdata starts with a pointer to call free() on followed by a pointer to call edj_free() on. The example above uses EDJFUNC_EDJFREE because the first field in the agwidest_t data type is a edj_t pointer.

Automatic freeing isn't just convenient; it's necessary. The final value function (jfn_widest() in the above example) can't be depended on to free it, because that function might never be called, depending on the edj expression it's used in.

The jfn_widest() function returns the longest string. It could have returned a edj_copy() copy of the string and then allowed EDJFUNC_EDJFREE to free the copy in the agdata, but it's more efficient to just return it directly and set the pointer in the agdata to NULL to prevent EDJFUNC_EDJFREE from freeing it.

Adding a function in src/lib/calcfunc.c

The built-in functions are all implemented in exactly the same manner as described above, with one difference: Instead of registering them via edj_calc_function_hook() or edj_calc_aggregate_hook(), they're directly added to the internal linked-list of functions, via a series of initialized variables. It looks clunky, but it allows us to avoid having something like a edj_init(). There is no edj_init() function because it isn't needed.
