Rationale

2026-08-08

This is a concise summary of decisions made, and more importantly why.

Why resemble JavaScript and SQL?

  • To reduce the burden on new/occasional users.
  • JavaScript's syntax is fairly "normal".
  • SQL is good with tables. jx has "native" table operators, but they aren't JavaScript so users aren't likely to guess them. They can guess SQL syntax though.

Why not full JavaScript?

  • Size. JS interpreters are huge, and they need to load all data into memory (no deferred arrays). JS also has many classes that have nothing to do with data.
  • JS isn't really that good at querying tables. jx's query language is better for that.

Why not object classes?

  • JSON data doesn't have classes.
  • OOP is a design methodology, but jx is mostly for ad hoc queries.
  • jx uses call-by-value, making it hard for objects to modify themselves.

Why make expressions without a command name be interpreted as output commands?

  • Convenience.
  • It's more like a web browser's debugging console.

Why add new operators?

  • Much JSON data is organized as tables. Table operators help a lot.
  • Some operators such as "i...j" help compensate for missing features. jx's use of "..." is NOT incompatible with JavaScript's "spread" and "fill" operators, so jx could get ... as a spread/fill later.
  • Other operators such as the low-precedence "expr..fn()" are useful as you incrementally refine a query.

Why do so many of the added operators use the "#" character?

  • The "#" character is used in table operators, because visually "#" looks kind of like a table.

Why use = and <> for case-insensitive comparison.

  • We needed one, and SQL uses those operators and is case-insensitive.
  • = is also used for assignment, to remain similar to JavaScript. This causes some compromise, though.

Why support ISO-8601 date/time/period arithmetic?

  • Many JSON documents use ISO-8601.
  • JavaScript's Date class is clunky, and jx doesn't use classes anyway.
  • It's beautiful!

Why plugins?

  • Security - don't load shell or network support if you don't need it.
  • Size - jx has many interactive features, which are useless in batch scripts.
  • Modularity - You can write your own plugin leaving the rest of jx unchanged.

Why don't batch scripts support persistent settings, like interactive jx?

  • This is intended to give batch scripts a consistent run-time environment. If a script needs a particular plugin or setting, then it should use the "plugin" or "set" command to ensure that it's there.

Why use fineline instead of GNU readline?

  • Fineline can run inside an ncursesw application (the -lscreen plugin)
  • Fineline supports multi-line input, which allows examples to be formatted properly.
  • Fineline's multi-line feature allows it to be used as an embedded text editor. This lets you revise function definitions without leaving jx.
  • Fineline has syntax coloring and hinting, which makes it easier to enter syntactically correct queries.
  • Fineline supports asynchronous "chat" display and code extraction, allowing for a decent AI interface.
  • Fineline uses common text editor conventions such as ^V for "paste". Users are more likely to be able to guess the correct key commands.

Why is fineline a separate project?

  • fineline isn't inherently tied to jx. It can be useful in other projects.
  • jx and fineline have different licenses. jx uses the normal GPL license, while fineline uses the weaker LGPL, making it easier to use in other projects (even closed-source ones). Using LGPL seemed appropriate since it's pretty much complete as-is, while jx will forever be tweaked and extended.

Why support AI?

  • Many users will use jx only occasionally. They might not remember all of the details or available features. AI can help.

Why does the C library implement arrays as a linked list?

  • It's easier to generate during parsing JSON data.
  • Most arrays get scanned from beginning to end anyway, so there's rarely a performance penalty.
  • It makes deferred arrays easier to implement.
