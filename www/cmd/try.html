try - Catch errors

try cmd catch catchcmd
try cmd catch (name) catchcmd
Execute cmd. If it fails (generates an error) then run catchcmd.

Usually cmd will be a pair of curly braces containing a series of commands. It can also be a single statement terminated with a semicolon.

If you provide a parenthesized name after the catch keyword, then a variable with that name will be created and set to an object describing the error, while the catchcmd is running. The members of the object are:

filenameThe name of the script file containing the code where the error was detected. If there is no applicable file name (such as for interactively entered commands), this member may be omitted.
lineThe line number within the script file where the error was detected. Also omitted for interactive commands.
keyA key (member name) intended to uniquely indicate the error type, and also guide translation to the user's preferred language.
messageHuman-readable text describing the error.
Examples
try { 1/0; } catch (err) { {Oops:err}; } {
  "Oops":{
    "key":"div0"
    "message":"division by 0"
  }
} The cmd contains a not-so-subtle division by zero error. This is caught, and the catchcmd is run with err set to an object describing the error. To keep this example simple, we just output it.
Notes
  • JavaScript allows a finally finalcmd clause as part of its try statement. edj doesn't support finally.
  • The "key" field, if present, is used to translate the message via the "messages" object. That object is loaded from a locale-specific file, typically /usr/share/edj/locale/$LC_MESSAGES/messages.json.
  • The "message" field of the error object is human readable. It may be translated, so if you want to detect specific error types then you should use "key" instead of "message".
  • In a future version of edj, the parenthesized name after the catch keyword may be extended to support a way to selectively catch some errors while allowing others to "percolate" out to either an outer try/catch or be reported to the user in the normal fashion. I've often wished JavaScript could do that, but they don't seem to be in a rush.
