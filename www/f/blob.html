blob - Manipulate or convert binary data

blob(data:string|array, convin?:number, convin?:number):string|array
A "blob" is a chunk of binary data. The name comes from SQL where it supposedly is short for "Binary Large Object". In jx, binary data is internally stored as compact bytes but externally it is presented as a deferred array of numbers representing the byte values.

The blob() function lets you convert the bytes to strings or vice-versa. By default, if you pass it a string it will return the bytes of the UTF-8 representation of that string; if you pass it an array of bytes it will convert those bytes to a string. You can also pass extra parameters to blob() to interpret a string differently, or to generate other formats. There is a Blob object which defines the following values that you can pass as conversion numbers:

Blob.any This tells blob() to make its own choice, by examining the data. This is the default input conversion.
Blob.string This tells blob() to choose a string type by examining the data. This is the default output conversion, when the input data is an array of bytes.
Blob.utf8 Interprets data as a UTF-8 string. If you pass an array of bytes that doesn't represent valid UTF-8 character sequences, you'll get an error.
Blob.latin1 Interprets data as a Latin-1 string. Latin-1 is a one-byte-per-character encoding that is limited to the first 256 UTF-8 characters. Internally, jx always stores strings in UTF-8, so if you request a Latin-1 conversion, you'll get bytes interpreted to Latin-1 converted UTF-8.
Blob.bytes Interprets data as random bytes. This is more useful as an output conversion than an input one, because it's pretty obvious when the input is an array of bytes.
Examples
blob("Test") [84,101,115,116] blob([84,101,115,116]) "Test" First we convert a string to a blob, which is represented as an array of byte values. Then we do the reverse to get the original string back.
blob("Test").deferTypeOf() "Blob" This shows that blobs are implemented as deferred arrays. You shouldn't be afraid to load up very large binary files.
Notes
  • The constants defined in the Blob object are negative numbers. This is so that blob() can some day be extended to allow byte offsets to return slices of binary data.
  • The charCodeAt() and fromCharCode() convert characters to numbers and vice-versa. The numbers are Unicode code points though, not byte values. If you're only dealing with the first 256 Unicode characters though, that's basically the same as Latin-1 which blob() can also handle, so there is some overlap of functionality here.
  • The curl plugin's unmime64() function can return a blob. It uses the same Blob.xxx constants to control the conversion style.
