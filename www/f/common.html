common - Show which values occur in each array

common(arrays:object|array, ..., style?:number)
This function gives you a way to to compare two or more datasets to see if anything is missing from some of them.

Given a set of arrays, common() returns a table with one row for each distinct value from those arrays. Each row includes the value, plus a column for each array indicating whether that value occurs in that array.

Arrays may be passed either as members of an object, or separately. The advantage of passing them in an object is that the member keys will be used to label each array's column. Arrays that are passed separately have no name, so their column labels will simply be letters.

You may also optionally pass a style argument to control the output format. If you don't pass a style argument then the value of config.common.style is used. The value is a number, representing a bitmap of available features. The's a Common object which defines constants representing the style features, and the idea is that you'll use a | (bitwise-OR) operator to combine the features you want. There's also a Common.bits field which you can use with nameBits() to decode a style. The style features are:

Common.index
Common.count
Common.check
Common.in		 You can choose one of these to select what gets shown in the column of an array that does contain the value. Common.index shows the index number within the array where the value occurs. Common.count shows how many times the value occurs in the array. Common.check shows a checkmark (or heavy checkmark if it's the only one in the row). Common.in shows the value of the config.common.in option, which is "Y" by default.
Common.all This controls whether the values that are present in all arrays should be included in the result. The are included in the default style, but you might want to turn off this bit to omit those rows, allowing you to focus on the rows that show missing data.
Common.inOnly
Common.outOnly
Common.mix
Common.none		 You can choose one of these to select what gets shown for rows where only some of the arrays contain the value (the opposite of Common.all). Common.inOnly shows rows where the value exists in only one array. Common.outOnly shows rows where the value is missing from only one array. Common.mix shows all rows where the value is missing from at least one array. Common.none doesn't show any rows where the value is missing from an array.
Common.stats This adds some extra rows to the result table, giving statistics about the status rows. These are:
  • length: number of items in each input array.
  • inOnly: number of rows where this array was the only one containing the value.
  • outOnly: number of rows where this array was the only one not containing the value.
  • spread: number of rows containing 1 match, 2 matches, etc.
Note that the values in the spread row don't correspond to individual arrays. The first column is always a count of rows with one matching value (i.e., rows whose value exists in only one input array) regardless of which array that value comes from. The second column does the same for rows with two matches, and so on.
Common.noSort Normally rows are sorted by the value column, similar to .orderBy("value") except that if you also use Common.stats then this will still leave the statistics rows at the bottom of the table. The Common.noSort flag disables this sorting.
Common.force The common() function works best on arrays of strings or numbers Normally the common function complains if you pass tables instead of arrays, mostly because the "value" column would just show "{object}" for every row. Not real useful. But common works for arrays of any type, including objects, and if you're doing further processing on the returned value then maybe it is useful after all? The Common.force flag allows you to use tables.
Common.recheck For the sake of speed, common() usually just compares the hash() number for each value. There's a slight chance that different values will have the same hash number though, which would cause the result table to be inaccurate. The Common.recheck flag causes it to compare both the hash number and the values themselves, using the "strict" rules of the === operator.

Notes
  • There are some options that affect the behavior of this function.
    set commandconfig constantMeaning
    set common.in=Yconfig.common.in:"Y"Mark to show in columns containing the value
    set common.out=""config.common.out:""Mark to show in columns not containing the value
    set common.style=4config.common.out:4Default style number
    set common.hashTable=10config.common.hashTable:10Size of hash table (2^n, so 10 means 1024)
  • The Common object also defines a Common.bits member which you can pass to the nameBits() function to decode a style number.
    nameBits(config.common.style, Common.bits, "|") "in|all|mix" This decodes the default style from config.common.style. The "all|mix" part of the settings means all value lines are shown (but not the statistics lines). The "in" part means if the value is present in an array, then the config.common.in value will be displayed.
  • Since this uses hash() numbers as the first test, it is subject to the quirks of that function. For example, integer 2 is different from floating point 2.0, and strings are case-sensitive.
  • The diff() function also compares two arrays. You'll probably want to use both of them at times.
