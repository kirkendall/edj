gap - Find gaps in an array of numbers or dates/times

gap(arr:number[]|date[]|time[]|datetime[], mingap?:number|period): table
This returns a table of the gaps that it finds in an array's values. The array should contain only numbers, or only ISO-8601 date strings, or time strings, or datetime strings. The values must be sorted in ascending order.

You can also specify a minimum gap to report. Only gaps greater than or equal to the minimum gap will be reported. If you don't specify a minimum gap, then a default will be chosen depending the array's data type. For numbers, the default is 2, so consecutive numbers won't show in the result table but if any integers are missing then they will show. For dates, the default gap roughly two days. For times and datetimes, the default gap is 90 seconds.

If you do specify a gap, then it should be either a number or an ISO-8601 period string such as "PT1H" for one hour. You can't use a period with an array of numbers, but you can use a number with an array of dates, times, or datetimes; the number will interpreted as days for ISO-8601 date strings, or minutes for times and datetimes.

The result is a table with 3 columns/keys:

index The subscript of item at the end of the gap. If you wanted to fill the gap, this is where you'd need to insert something.
previousThe value of the item before the gap.
nextThe value of the item after the gap.

 In the first example, since no minimum gap was specified, we use the default for an array of numbers, which is 2. Note that gaps much larger than 2 still only generate one row in the response.

In the second example, we use the same array but pass an explicit minimum gap of 1. Since all integers are at least 1 apart, all of the spaces between them get reported.

["12:00:00","12:00:15","12:00:45"].gap("PT20S")
indexpreviousnext
212:00:1512:00:45
 Here we're scanning an array of ISO-8601 time strings for a gap of 20 seconds or more. The first two times are only 15 seconds apart so that isn't reported as a gap. The last two times are separated by 30 seconds, so that is reported. The index of the "next" item is 2.
Notes
  • This can't report gaps before the first item or after the last item.
  • You can't search for gaps in a table, directly. However, it's easy to extract a column from the table and do the gap scanning on that.
    gap(ClosedPurchaseOrders.orderBy("po") # po) First we sort by "po" because the gap() function requires its array to be sorted, and then we use the # operator to extract just the "po" column. The gap() function then reports any missing "po" numbers.

    If the "po" member's value looked like number but was represented as a string, then you could use "#po.parseInt()" instead of just "#po", to get an array of numbers that gap() can use.
