grep - Return array elements containing a given value

grep(haystack?:array, needle:number|string|regex|null, key?:string, ignoreCase?:true ) :table
grep()does a deep search through elements of an array, and returns only the elements that contain a given value. No matter how deep the matching value is buried, the whole element will be returned. Elements containing multiple matches will only be included once.

If you don't specify an array to search through, then it'll use the default table (the same one that SELECT uses without a FROM clause). The explain ? command will tell you where the default table is located.

The needle may be a number, string, regular expression or null. If it is a string, the search will be case-sensitive unless you also pass a true argument to make it case-insensitive. If it is a regular expression, then grep() will look for text matching that regular expression within any string in the data. When needle is a string or regular expression, then it will only match strings; if it is a number then it will only match numbers except that an integer number may match a digit string. When needle is null, it will match any value; this is most useful when used with a key argument.

If you pass an optional key argument, then the search will be limited to finding object members with the given key. The key is given as a string, so use quotes. For example, if you wanted to find part#199 in an array of invoices, where each invoice contains an array of parts, then you could pass "partno" as the key to prevent 199 from matching other members such as price.

The result is a subset of the haystack array.

Examples
["one","two","three","four","five"].grep(/o/) ["one","two","four"] Here we're searching for strings containing the letter "o". Three elements' values match, so that's what we get in the result.
[3,"three","3","03"].grep(3) [3,"3"] When searching for an integer, it can also match a string of digits that "looks like" the integer.
test.cust.grep("Portland")
namecontactjoined
Peter[table]2024-01-02
Ziggy[table]2023-04-17
 test is part of the sample data. We're searching for the string "Portland" in the "cust" table, and find it in two rows. The value is actually found somewhere inside the "contact" tables within those two rows.
Notes
  • This is a lot like the find() function. The main difference is that grep() returns whole elements from the haystack array, while find() returns a list of matches. The arguments for both functions are identical except that grep() requires the haystack to be an array, while find() can search through an object or array.
  • Passing a true parameter won't make regular expressions be case-insensitive. Instead, do that by appending the letter "i" after the regular expression's closing "/" character.
  • Regular expressions normally look for matching text anywhere within a string value; it doesn't need to exactly match the whole string. If you want to require the regular expression to match the whole string like a string needle would, use the ^ and $ metacharacters.
    test.cust.grep(/^portland$/i)
    namecontactjoined
    Peter[table]2024-01-02
    Ziggy[table]2023-04-17
     This searches for "portland" with no extra characters before or after it. Because the regular expression is followed by an "i" flag, the search is case-insensitive.
