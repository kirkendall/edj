length - Return the length of an string or array

str.length
arr.length
This returns the number of characters in a string, or the number of elements in an array. It isn't really a function, so you aren't expected to put parentheses after the name.
Examples
"Fortune".length 7 There are 7 characters in "Fortune".
["North","East","South","West"].length 4 There are 4 elements in the array.
Notes
  • Probably this should have been a function, but it isn't in JavaScript so for the sake of compatibility it isn't here either.
  • This is often used to loop over the elements of an array. When doing that, remember that array subscripts start at 0 so the highest subscript is length-1.
    for (i = 0 ... config.styles.length - 1) print config.styles[i].style + "\n" normal
    prompt
    result
    error
    debug
    gridhead
    gridcell     The config.styles array stores the colors and other character attributes that jx uses for various meanings. Here we're looping over the array and printing the style names. Note the use of length-1 in the for-loop.
  • Since some Unicode characters are zero-width and some are double-width, length and width are different. See the widthOf() function for width.
  • In UTF-8, the number of bytes required for each character varies. length counts characters, not bytes. If you want to count the number of bytes in a string, probably the cleanest way to do it is to convert the string to hexadecimal and divide the hex string's length by 2.
    const smile="\U0001f600" smile.length 1 smile.width() 2 smile.hex().length / 2 4 First we define smile to be the smile-face emoji. Its length is 1 character, but its width is two columns, and its internal UTF-8 representation requires 4 bytes.
  • JavaScript uses UTF-16 internally, so characters outside Unicode's Basic Multilingual Plane must be represented by surrogate pairs. This causes JavaScript to count some characters (such as emoji) as having length 2. In jx, though, all characters are counted as having length 1.
  • Attempting to use length on an object will yield weird results. If the object actually contains a member named "length" then that will be returned. Otherwise 1 is returned, because that makes some XML-tainted data easier to process.
