money - Convert a number to a money string or vice versa

money(money:number, format?:string="%i") : string
money(moneystr:string) : number
When passed a number, the money() function converts it to a currency string in the locale's format. You may optionally pass a format string, using the same conversion specifiers as C's strfmon() function. (See "man 3 strfmon".) If you don't pass a format string, then "%n" is used, which the basic national format.

When passed a string, it strips out all characters except digits, the decimal point, and a negative sign, and converts that back into a number.

Examples
123456.money() "$123,456.00" This converted 123456 (dollars in my locale) to a currency string.
(-1.98).money() "-$1.98" This converted -1.98 dollars to a currency string. The locale rules say the minus sign goes before the dollar sign. Also, the number had to be in parentheses because the "." operator has a higher precedence than the "-" operator.
(-1.98).money("[%(12i]") "[ (USD 1.98)]" This time we're passing a format string to use instead of the default "%i". We have square brackets around the format; since there aren't part of a %n or %i conversion specifier, they'll be treated as literal characters.

The "%(12i" is a conversion specifier. The "(" means negative numbers should be enclosed in parentheses instead of using a negative sign. The "12" means the value should be padded to be 12 characters wide, which is why the result string shows two spaces after "[". The "i" means it should use the international currency designator instead of the national one ("USD " instead of "$").

"[ (USD 1.98)]".money() -1.98 This strips out all of the formatting to return just the number.
Notes
  • Although C's strfmon() function can convert multiple money values in a single call by having multiple %n or %i conversion specifiers in the format string, jx's money() only allows a single %n or %i.
  • Money values are represented by a floating point number, where 1.0 represents one euro/dollar/etc. However, the value 0.01 can't be exactly represented in a binary floating point number, so long chains of money calculations can lose precision. You might consider some other representation in your calculations (e.g., an integer representing cents instead of dollars) and only convert to double when you want to output it via money().
