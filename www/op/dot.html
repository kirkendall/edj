Dot operators

object.key
function(...)		Access a member of an object by key (name)
object..key
function(...)		Access a member (low precedence)
object.@keyAccess a deeply nested member
The . operator lets you access a member of an object by its key (name). It can also be used to invoke a function, using the left hand argument as the first function parameter; this lets you invoke functions as though they were member functions of an object, even though jx doesn't really support object classes.

The .. (double dot) operator is exactly like . except that .. is parsed with a very low precedence, while . has a very high precedence. This is intended to make it easy to compose and test complex expressions in small steps.

The .@ operator is similar to . but it does "deep" lookup, meaning if the object doesn't have a member with the given key but does contain members whose values are objects, then it will search for the key in those objects too.

Examples
test.deep {"deeper":{"deepest":3,"deeply":"madly"},"dept":"transportation"} test refers to the "test.json" table in the sample data, assuming you invoked jx as "jx -dsampledata". Here we're accessing the deep member of the object in that file.
test.deep.deeper.deepest 3 test.@deepest 3 First we use a series of . operators to navigate down through a series of nested objects. Then we get the same result using the .@ operator once.

If we used a single dot operator (.orderBy(...)) then we would need to add parentheses around the first expression since . is a high-precedence operator. But .. is a low-precedence operator so we don't need to add parentheses.
Notes
  • The object.@key operator is only smart about descending into nested objects. It is not smart enough to scan arrays for a match.
